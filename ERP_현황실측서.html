4. 완료 성과 (보고서 「성과」장 신설 권고)

  • 클라우드 1단계 이행 — 전 화면 Supabase app_state 연동, 집↔사무실 실시간 공유
  • supabase 로컬 내장 — 외부 CDN 차단(회사망) 대비 라이브러리 내장, 37화면 적용
  • 비상신고 모바일 배포 — 이상안전신고 6개 언어 + 사진첨부 + QR 포스터 + PWA 홈화면
  • 브랜드 로고 표준화 — SJ 로고(감청/흰색/검정 3종) + SVG/PNG/ICO + 의미·사용 문서
  • ISIR PDF 아카이브 — 성적서 18건 + 원본 PDF 보관 + 품번 클릭 열람 + 엑셀 입출력
  • 도면관리 기준정보 이관 — 회사 전 데이터 기준(도면)을 기준정보 대분류로 재배치
  • 메뉴 클라우드 구동 — map_struct 기반 21 대분류 전 PC 자동 반영

5. ⚠️ 저장소 비대화 — 즉시 관리 필요 (4권 반영)

현재 저장소 2.4GB. 구성: ISIR PDF 445MB + legacy.html 50MB + git 이력 누적(legacy를 v1→v379 반복 커밋 시 이력에 매 버전 50MB 적재). GitHub 권장 저장소 <1GB를 이미 초과.
원인영향개선 방향
대용량 스캔 PDF(445MB)push 느림·저장소 비대NAS/오브젝트 스토리지로 분리 + 링크만 유지(승정나스 활용)
legacy.html 50MB 단일파일매 커밋 이력 누적·첫 로딩 지연화면 분할(모듈별 파일) + 인라인 이미지 외부화
git 이력 누적clone/pull 지연·GitHub 한도대용량 이력 정리(git-lfs 또는 신규 저장소 이관) — 신중 진행
권고: 대용량(PDF·이미지)은 저장소 밖(NAS/스토리지)에 두고 ERP는 링크만 갖는 구조로 전환. 4권 「Cloud/운영전략」에 "저장소 경량화" 항목 신설.
